# Day 11 — Chrome DevTools Network Observation

**Test Website:** https://the-internet.herokuapp.com/

**Observation Date:** 2026-10-12

**Tool:** Google Chrome DevTools — Network

**Test Focus:** HTTP Requests, Responses, Status Codes, Redirects, and Network Inspection

## 1. Objective

Observe HTTP requests and responses during page loading, successful login, and logout using Chrome DevTools.

## 2. Test Activities

1. Open the website in Google Chrome.
2. Open Chrome DevTools and select the Network tab.
3. Inspect the requests generated during page loading.
4. Use request-type filters such as All, Doc, CSS, JS, and Fetch/XHR.
5. Open individual requests and inspect their Headers and Response.
6. Enable Keep log to preserve requests across page navigation.
7. Perform a successful login and inspect the related requests.
8. Log out and inspect the redirect back to the login page.

## 3. Observed HTTP Requests

| Action | Request | Method | Status | Observation |
|---|---|---|---|---|
| Load home page | `/` | GET | 200 | The home page loaded successfully. |
| Load JavaScript resource | `/js/foundation/foundation.js` | GET | 200 | The script was loaded, with the response served from memory cache. |
| Submit valid login | `/authenticate` | POST | 303 | The server redirected the browser after login. |
| Open secure page | `/secure` | Not separately verified | 200 | The secure page loaded successfully. |
| Log out | `/logout` | Not separately verified | 302 | The browser was redirected after logout. |
| Return to login page | `/login` | Not separately verified | 200 | The login page loaded successfully. |

**Note:** Request methods marked "Not separately verified" were not confirmed from the captured Headers screenshots.

## 4. Headers Observation

During successful login, the following information was observed:

- Request URL: `https://the-internet.herokuapp.com/authenticate`
- Request Method: `POST`
- Status Code: `303 See Other`
- Location: `https://the-internet.herokuapp.com/secure`

The Location response header identified the destination of the redirect.

## 5. Response Observation

The Network panel was used to inspect response content.

For example, the `foundation.js` request displayed JavaScript source code in the Preview and Response tabs.

The response Content-Type was `application/javascript; charset=utf-8`.

The login redirect response had a Content-Length of `0` in the captured Headers view.

## 6. Status Code Interpretation

- **200 OK:** The HTTP request succeeded.
- **302 Found:** The server issued a temporary redirect.
- **303 See Other:** The server directed the browser to another resource, typically retrieved with GET.
- **Failed request:** A network request did not complete successfully. Its cause must be investigated before reporting an application defect.

## 7. Additional Observation

A failed request to a third-party analytics domain (`298279967.log.optimizely.com`) appeared in the Network panel.

This failure was observed alongside successful page navigation. The available evidence does not establish that it caused a user-facing application defect.

Requests generated by browser extensions or translation tools were also visible. These should be distinguished from requests originating from the application under test.

## 8. Conclusion

Chrome DevTools Network was used to inspect HTTP requests, response status codes, headers, response content, and redirects.

The successful login and logout navigation flows were observed, including HTTP 303 and HTTP 302 redirects.

No defect in the observed login or logout navigation flow was confirmed during this exercise.
